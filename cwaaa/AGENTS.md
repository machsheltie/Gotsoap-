## Boundaries

CWAAA is A Coalition Making Its Case in Public. Use Recovery Stories and Chapters in navigation. The coalition validates, documents, and organizes; ordinary pages have no regulatory voice. CWAAA owns both pledge email fulfillments: immediate receipt and one current issue, with one shared Buttondown audience. Typography proposals are not owner approvals; follow the current local UI authority.

Intentional uncertainty is not missing documentation. Do not explain the CWAAA/Office relationship, add a clean handoff, or average their rendered authorship. The canonical IVR is the controlled exception in shared artifact authority.

## Working files

Documentation belongs in this folder. Current runtime work remains in [../site/](../site/) and follows [../AGENTS.md](../AGENTS.md) plus [the current runtime contract](../specs.md). The nonprofit's existing `public/` assets are preparation, not proof of a working standalone site. Do not delete combined-runtime CWAAA material before the migration manifest's replacement and verification steps succeed.

Before campaign copy work read [the copy protocol](../gotsoap/docs/copy/COPY-PROTOCOL.md), the applicable local voice authority, and `../site/src/content/copy.ts`. Editing organization or references does not authorize changing approved copy.

Keep shared canon and contracts under `../docs/`; reference them rather than inventing independent versions. Keep cross-domain config empty until real domains are assigned. Preserve license and attribution constraints. Do not read, parse, move, or stage brush files; keep large Photoshop sources in place.

## Verification

Run the repository-required build, font audit, gates, copy-gates, fidelity, distinguish, and authority checks from `../site/`. Check the Git root before staging; do not use `git add -A`. This folder is part of one repository, not an independent Git repository or deployment.
